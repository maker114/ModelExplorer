### V3.5.0

#### 配色预设

- **12 套预设整体换新**（数量不变，仍是 12 套）。新配色取自
  [520设计网「色彩搭配」](https://www.sj520.cn/tools/peise/) 的公开方案：该页共 520 组四色，
  先筛掉整体偏亮、压到深色界面上读不清的，再按强调色色相在色谱上均匀取 12 组，
  于是**覆盖 12 个不同色系**：

  | 色谱位置 | 预设名 | 强调色 | 色谱位置 | 预设名 | 强调色 |
  | --- | --- | --- | --- | --- | --- |
  | 红 | **丹砂**（默认） | `#FC4646` | 青 | **碧落** | `#14FFEC` |
  | 橙 | **柿子橙** | `#FF6C00` | 天蓝 | **晴山** | `#8DC6FF` |
  | 琥珀 | **金珀** | `#FFD700` | 蓝 | **玄青** | `#7C78EF` |
  | 黄绿 | **柳芽** | `#B5FF7D` | 紫 | **紫棠** | `#EFB1FF` |
  | 绿 | **翠微** | `#4EF037` | 品红 | **品红** | `#D84AE2` |
  | 青绿 | **竹青** | `#45EBA5` | 玫红 | **胭脂** | `#FB2A94` |

- 原站每组是**平铺四色**（没有主次），所以强调色取其中最饱和的一色、最暗一色压暗成
  底 / 侧栏 / 面板 / 描边阶梯（底色只带约 24 % 饱和度，避免整片被强调色染色）。
- 旧配置里若保存的是已删除的预设名（例如「苔原绿」），会自动回退到默认的**丹砂**。
- **颜色与测试版逐位一致**：这批方案在测试版里实际走的是「构造时压一遍 0.62 + 套用测试数据
  时再压一遍 0.62」，正式版照同一数值复刻——丹砂强调色 `#FC4646` 显示为 `#AD6868`，
  实机取色与当时的测试版截图完全相同。
- 降饱和不再就地改写预设对象：源码里始终是原始饱和度，界面取用按 `SoftnessRatio` 现算的
  那份；想整体收紧或放松只改这一个常数，不必再动 12 套色值（改完等于换一套观感）。

### V3.4.9

#### 配色

- **类型标签色改为同色相的三档明度**：V3.4.8 把三个色相拉得太开（零件的 −15°、装配体 +35°、
  STL −150°），区分度是有了，但暖色主题里挂一个冷色标签、冷色主题里挂一个暖色标签，
  看着不像一套配色。现在三色只差**明度与饱和度**：零件最亮最淡、装配体居中、STL 最深最实
  （明度 0.88 / 0.74 / 0.62，饱和度 0.42 / 0.50 / 0.56），每个主题读起来就是「一个色系的三档深浅」。
  最暗的一档仍保证对面板色 4.5:1 以上对比度（12 套实测最低 4.5:1、最高 14.2:1）。
- 强调色本身几乎中性时（石墨灰）不再借用某个色相，改为一条中性灰阶。
- 三方案对照（现行冷暖分离 / 同色系窄带 / 同色相明度档）见 `work\HslProbe\SchemeProbe.cs` 与
  `work\glass\palette-groups.png`。

### V3.4.8

#### 配色

- **类型标签色改为按配色推导**：「零件 / 装配体 / STL」三组颜色原先是 12 套预设里逐套手写的，
  STL 有 11 套写的是蓝色系（`#8FC7FF` 一个值出现 4 次），V3.4.2 统一降饱和后蓝色彼此更分不开，

- 三色对面板色的对比度最低 4.7:1（暖阳金的 STL），仍在可读区间。

#### 设置界面

- **所有预设统一降饱和**：每套配色的所有颜色都按同一比例（保留 62 % 饱和度）向等亮度灰靠拢。

  「石墨灰」这类本来就中性的预设几乎不受影响。

### V3.4.1

#### 毛玻璃

- **玻璃材质改为无色**：面板、侧栏、悬停态的填充与描边都去掉了色相、只保留明度。
  此前填充用的是主题面板色，于是熔岩红这类主题会把整片侧栏染成红色半透明，压在壁纸上
  像蒙了一层色纸。磨砂玻璃本身不吸色——主题色现在只出现在强调色、文字与状态色上
  （实测熔岩红 + 壁纸时，侧栏分区框与列表卡片的 R−B 由明显偏红变成 −1～−3）。
- 关闭毛玻璃、或把透明度拉到 0 时，画刷仍然回到原来的主题实色，观感与 V3.1.3 一致。

#### 配色预设

- 预设从 6 套增加到 **12 套**，新增：**石墨灰**（完全中性，配壁纸最百搭）、**深海青**、
  **樱花粉**、**靛蓝**、**赤陶橙**、**苔原绿**。
- 因为玻璃材质已经无色，预设之间的差异主要体现在强调色、文字与状态色上；

### V3.4.0

#### 毛玻璃

- 原来的三档强度换成两个滑杆，拖动即时预览：
  - **模糊** 0～60 px：作用在整层背景上，极光与自定义背景图一起变糊；
  - **透明度** 0～100 %：0 = 面板不透明（背景被完全挡住），100 = 只剩边框。
- 旧配置里的三档强度会**自动换算**成等价的滑杆值（轻柔 → 26 px / 14 %，标准 → 40 px / 26 %，
  浓郁 → 56 px / 38 %），升级后观感不变。
- 设置里不再重复提供「壁纸模糊」——两个滑杆控制的是同一件事，留一个即可。

#### 背景图

- **清晰度**：背景位图改为按显示器缩放绘制。150% 缩放下，同一个窗口的位图从 600×390
  提到 1800×1170（像素与屏幕一一对应），不再被放大三次；实测局部细节提高约 1.9 倍。
- **不再被主题染色**：设置了背景图时不再叠加主题色极光，窗口保持透明、颜色由你的图决定
  （实测背景色 R−B ≤ 0，没有主题黄）。留白区域仍用主题底色。
- 「适配」分段按钮的未选中文字改为常规文字色。

#### 修复

- **适配按钮选中态文字看不清**：控件构造时赋的 `Foreground` 是本地值，优先级高于模板触发器，
  选中态颜色一直被它盖掉，强调色底上压着灰字。改为在模板里直接对 `ContentPresenter` 设色。
- **背景图分区标题下的分割线贴到了输入框上边框**，两行并成一条粗线；路径行补上 8 px 上边距。
- **工程名检查弹窗的列表、设置里下拉菜单的选项改回不透明**：这两处文字密集，透出壁纸只会更难读
  （实测弹出层内部高频能量 1.02，同屏正文 8.32）。

#### 版本

- 主程序 / Core / CLI / 测试更新至 3.4.0；SolidWorks 插件本次无改动。
- 新增 16 项配置回归测试（滑杆持久化、越界夹取、旧三档强度的迁移优先级），测试总数 124 → 140。

### V3.3.0

#### 背景图

- 新增**自定义背景图**：「设置 → 背景图」可以选一张本地图片作为窗口背景，主界面与 6 个
  对话框共用同一张，观感统一。没有设置时仍是原来的极光背景。
- 四种**适配**方式，区别写在设置项下面：
  - **覆盖**（默认）：等比放大铺满窗口，超出部分裁掉，不留空；
  - **填充**：等比缩放到完整可见，四周用极光底色补齐；
  - **居中**：不缩放，原尺寸居中；
  - **拉伸**：非等比拉伸铺满，比例可能与原图不同。
- **壁纸模糊** 0～40 px（0 = 不模糊）与**暗化** 0～90 %。未设置背景图时模糊滑杆不生效，
  极光仍按玻璃档位自动模糊。
- 选图、适配、模糊、暗化都会**立刻预览**（直接重画当前所有窗口的背景层），点「保存」
  才写进 `config.json`；取消或直接关窗会把预览还原，不会出现「界面与配置不一致」。

#### 显示开销

- 毛玻璃背景层从「挂在视觉树上的 `BlurEffect`」改为**一次性烘焙位图**：底色、背景图、极光
  先画进离屏位图，模糊、暗化、颗粒都在像素上一次算完并冻结，之后每帧只是贴一张位图。
  效果开销因此与模糊半径、光斑数量彻底脱钩，背景图也几乎不增加绘制成本。
- 背景图解码按长边 2560 降采样，同一路径跨窗口只解码一份；窗口尺寸变化后按 120 ms 防抖重建，
  拖动过程中先拉伸旧位图。
- 实测（本机、150% 缩放、99 个模型的工程）：

  | 场景 | 静置 | 连续改尺寸 | 滚动列表 | 内存 |
  | --- | --- | --- | --- | --- |
  | 3.2.0（实时模糊） | 0% | 约 1.73 CPU 秒 / 3.97 s | 16.6% | 113 MB |
  | 3.3.0（预烘焙，无背景图） | 0% | 约 1.67 CPU 秒 / 4.0 s | 17.2% | 124 MB |
  | 3.3.0（预烘焙，1600×1000 背景图） | 0% | 约 1.6 CPU 秒 / 4.0 s | 25.2% | 130 MB |

- **结论要说清楚**：改尺寸时那 ~1.7 CPU 秒并不是模糊造成的。对照实验里，
  完全没有背景层的 V3.1.2 是 1.73 CPU 秒 / 3.99 s，与开启毛玻璃后基本一致；
  真正的原因是 `AllowsTransparency=True` 的分层窗口在软件渲染下整窗重绘。
  预烘焙解决的是「效果开销随参数增长」与「背景图的边际成本」，不是这个固有开销。
  若要把这部分也压下去，唯一有效的杠杆是改用不透明窗口（`AllowsTransparency=False`）：
  同一份代码只改这一项后实测 **1.16 CPU 秒 / 2.84 s、内存 104 MB**（约 −33% CPU、−29% 耗时、
  −20 MB），代价是窗口不能再逐像素透明——圆角与外部阴影要看 Windows 11 的 DWM 是否提供。

#### 可读性

- 背景图会被自动压暗到一个**可读性下限**：先按用户给的暗化压一遍，再量直方图高分位，
  超过下限就整体等比压下来。下限按最严的一处反推——对话框里 11px 的说明小字是**直接压在
  背景层上**的，要让它保持 4.5:1，背景峰值就必须 ≤ 约 68，这里取 56 留出极光与颗粒的余量。
- 实测最坏情况（纯亮图 + 暗化 0）：背景峰值落在 59～61，
  小字压在背景上 **5.0～5.2:1**、压在面板上 **5.7～5.9:1**，三档玻璃强度都满足。
- 极暗或正常亮度的壁纸不会触发下限，滑杆效果如实生效；暗化滑杆的语义因此是「只会更暗」。

#### 版本

- 主程序 / Core / CLI / 测试更新至 3.3.0；SolidWorks 插件本次无改动。
- 新增 15 项配置回归测试（壁纸字段的缺省、回退与越界夹取），测试总数 109 → 124。

  工程名计划）。对话框统一走 `UiFactory.CreateWindowChrome`，毛玻璃只在那里接一次。
- **为什么不做系统亚克力 / Mica**：主窗口是 `AllowsTransparency=True` 的分层窗口
  （`MainWindow.xaml`），DWM 的背景模糊对它不生效或表现为黑屏；那套接口还会逼我们放弃
  逐像素透明、把桌面内容透进来干扰阅读。所以背景与模糊都在窗口内部自己做。
- **为什么可以放心用 `BlurEffect`**：极光层是静态的，模糊只算一次并被 WPF 缓存，面板完全不参与
  模糊；逐帧重算的实时模糊（`VisualBrush` + `Effect`）在软件渲染的分层窗口下代价太高，刻意不做。
- **为什么不透出桌面**：毛玻璃只画在窗口自己的不透明底色之上。分层窗口一旦整体半透明，就会直接
  透出桌面或下层窗口，压在上面的文字必然不可读。
- 可读性约束：极光透明度按「对话框那种小窗口会整片暴露」的最坏情况定档，保证 `#B0B0B0` 小字

## 功能规则说明

### 详细统计

- 点击左侧「统计」框（或其中的“点击查看详细统计…”）打开详细统计窗口，按**归属文件夹**
  列出零件、装配体、STL、3MF 的数量与总计。
- 工程只有一个文件夹时同样可以打开——详细窗口是查看 STL / 3MF 数量的入口
  （左侧统计框只显示零件、装配体与文件总数）。
- 位于 `STL文件夹` / `3MF文件夹` 中的文件**不会单独成行**，而是归入其所属的上级文件夹：
  例如 `工程\子工程\STL文件夹` 里的 STL 计入 `工程\子工程` 一行。这样分类文件夹不会
  产生额外行，同时各类文件的数量都能统计到。
- 尚未扫描到任何文件时点击会提示，不弹空窗口。

### 工程名整理 / 自动命名

- 当前“工程名”取当前选择工程目录的根文件夹名称。
- 根目录下的直接子文件夹会被识别为“子工程”，但 `STL文件夹` 和 `3MF文件夹` 不参与子工程识别。
- 子工程文件夹中的文件目标名使用 `工程名_子工程名_文件名`，例如根目录 `Model`、子目录 `Sub` 中的 `Part.sldprt` 会整理为 `Model_Sub_Part.sldprt`。
- 子工程文件夹内的文件若已带有工程名前缀但没有对应子工程前缀，会补齐为 `工程名_子工程名_文件名`。
- 普通零件 `.sldprt` 与 STL 文件名中，第一个 `_` 之前的部分视为旧工程名；没有 `_` 时视为没有工程名。
- 无工程名时生成“添加名称”：
  - `零件A.sldprt` → `工程名_零件A.sldprt`
  - `文件B.stl` → `工程名_文件B.stl`
- 已有工程名但前缀不等于当前工程根文件夹名时生成“修改”：
  - `旧工程_零件A.sldprt` → `工程名_零件A.sldprt`
  - 比较不区分大小写；前缀正确时不再改动。
- 装配体导出的 STL 使用另一条规则：
  - 只要文件名包含 ` - `，就按装配体导出 STL 处理。
  - 忽略 ` - ` 之前的内容，并取其后第一个 `_` 后面的部分作为主体。
  - 目标名保留当前工程名前缀，并在扩展名前追加 `[装配体导出]`。
  - 示例：`任意装配体名 - 任意旧工程_零件C.stl` → `当前工程名_零件C[装配体导出].stl`
  - 位于子工程文件夹时使用 `工程名_子工程名_主体[装配体导出].stl`。
- 工程名整理弹窗会显示“修改”和“添加名称”两类计划，并按文件类型分组：零件、装配体导出、STL。
- 弹窗顶部会醒目标出根工程名和本次涉及的所有子工程名，表格包含子工程列并优先按子工程名排序。
- 每个计划行默认勾选；上次执行时取消勾选的文件路径会保存，下一次仍默认不勾选。
- 只有勾选的项目会执行；执行时会跳过源文件已不存在或目标文件已存在的项目，不会覆盖同名文件。
- 已执行的工程名修改可通过“工程名整理”框中的“撤销工程名修改”反向恢复。
- 如果先执行工程名整理、再执行文件整理，两侧撤销记录会自动重定向，避免文件被移入分类文件夹后无法撤销工程名。

### 未整理 / 未对应标签

- `[未整理]` 只用于 STL 文件：
  - 文件不在当前工程根目录下的 `STL文件夹` 或 `3MF文件夹` 中时显示 `[未整理]`。
  - 已在分类文件夹中时不显示。
- `[未对应]` 用于 STL 文件：
  - 扫描时收集所有 `.sldprt` 与 `.sldasm` 的主文件名作为来源集合。
  - 如果 STL 主文件名在来源集合中不存在，则显示 `[未对应]`。
  - 比较时忽略 `[装配体导出]` 标记。
- 装配体导出 STL 豁免 `[未对应]` 检查：
  - 文件名包含 ` - `，或文件名带 `[装配体导出]`，统一视为装配体导出。
  - 这类文件不再显示 `[未对应]`，但仍会按目录位置判断是否显示 `[未整理]`。
- 右侧“选中模型”详情也遵循同一规则：装配体导出 STL 不显示“未对应/已对应工程文件”行。

### 自动整理 STL / 3MF

- 在左侧“文件整理”框中点击“整理 STL / 3MF 文件”执行。
- 程序递归扫描当前工程目录，但会跳过已有的 `STL文件夹` 与 `3MF文件夹`。
- 已经位于 `STL文件夹` / `3MF文件夹` 中的文件不会被再次移动：即使关闭“按文件夹整理”，
  它们也不会被重新汇总到工程根目录。若本次没有任何文件需要移动，程序会明确提示
  “没有需要移动的文件”并列出已归类数量，而不是毫无反应。
- `.stl` 文件移动到 `STL文件夹`，`.3mf` 文件移动到 `3MF文件夹`。
- 关闭“按文件夹整理”时：
  - 所有 STL 集中到工程根目录的 `STL文件夹`。
  - 所有 3MF 集中到工程根目录的 `3MF文件夹`。
- 开启“按文件夹整理”时：
  - 在每个文件所在目录下分别创建/使用 `STL文件夹` 或 `3MF文件夹`。
- 目标位置已有同名文件时会自动追加 `_2`、`_3` 等序号，不会覆盖已有文件。
- 整理完成后会删除空的分类文件夹，生成整理报告，并重新扫描刷新列表。
- “撤销整理”会按相反顺序把本次移动的文件移回原位置。

### 毛玻璃

- 开关与两个滑杆在**设置 → 毛玻璃**里：模糊（0～60 px）与透明度（0～100 %），拖动即时预览。
  关闭开关或把透明度拉到 0，所有画刷回到不透明实色，观感与 V3.1.3 一致。
- 背景图在**设置 → 背景图**里（选图 / 适配 / 暗化），六个窗口共用同一张；模糊共用毛玻璃的滑杆。
- 玻璃效果由三部分组成：
  - `Backdrop.cs` 负责「被透过去的那层背景」——底色、可选背景图、极光，以及模糊、暗化、
    颗粒；这些都在离屏位图上一次算完并冻结，运行期只是贴图。位图按显示器缩放出图，
    高分屏下像素与屏幕一一对应。
  - `Glass.cs` 负责把这张位图按窗口尺寸挂上去、尺寸变化后防抖重建、按窗口圆角裁剪；
  - `AppTheme`（`Theme.cs`）负责玻璃画刷——半透明填充（纵向略亮上暗下）、提亮的边框。
    透明度为 0 时它返回的就是旧版实色画刷，所以关闭毛玻璃不需要任何额外分支。
- 极光颜色直接取当前主题已有的强调色 / STL 色 / 装配体色，因此 12 套预设各有各的色相；
  但**设置了背景图时不再叠加极光**，窗口保持透明、颜色由背景图决定。
- 列表与下拉菜单用另一套**不透明**画刷（`OpaquePanelBrush`）：工程名检查弹窗的表格、
  下拉弹出层的选项都属于文字密集区，透出背景只会更难读。
- 背景图的亮度会被自动压到可读性下限以内（见更新报告 V3.3.0「可读性」），
  所以亮色壁纸不会把面板上的小字压没。
- 滑杆只影响透明度与模糊半径，不改布局；文字颜色与字号仍由主题与「字体大小」控制。

## 构建

项目为 5 个工程的标准 solution：

| 工程 | 说明 |
| --- | --- |
| `ModelExplorer.Core` | 共享业务库：扫描、工程名规则、整理、配置、STL 导出、Bambu 启动 |
| `ModelExplorer` | WPF 主程序（界面与主题） |
| `ModelExplorerCli` | 命令行转换工具 |
| `ModelExplorerAddin` | SolidWorks 2022 插件 |
| `ModelExplorer.Tests` | 测试套件（命名规则、扫描、整理、撤销） |

一键构建并运行测试：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

发布便携版（目录名按程序集版本生成）：

```powershell
powershell -ExecutionPolicy Bypass -File .\publish.ps1
```

发布结束后会自动清理 `dist\` 中的旧版本：**默认只保留最新 3 个版本目录**
（当前版本 + 2 个历史版本），更旧的删除。也可以单独运行清理：

```powershell
powershell -ExecutionPolicy Bypass -File .\prune-dist.ps1
powershell -ExecutionPolicy Bypass -File .\prune-dist.ps1 -KeepVersions 2   # 只保留 2 个
```

`prune-dist.ps1` 依据目录名里的**版本号**排序（而不是修改时间），因此手工重排过目录
也不会误删较新的版本。若某个旧版本的程序正在运行、目录被占用，脚本只提示、不删除，
关闭该程序后重跑即可。

> 发布前请先关闭正在运行的 ModelExplorer：`publish.ps1` 需要覆盖同名版本目录，
> 程序在运行时目录内的 exe / dll 被占用，脚本会明确提示这一点而不是抛出原始错误。

单独构建主程序仍可双击 `ModelExplorer\build.bat`。也可用 Visual Studio / VS Code
打开 `ModelExplorer.sln`，5 个工程全部已纳入。

输出到 `bin\Release\`，运行其中的 `ModelExplorer.exe` 即可。

所有工程共享仓库根目录的构建配置：`Directory.Build.props`（目标框架、平台、
Interop 路径）与 `lib\SolidWorks\`（SolidWorks Interop 程序集的唯一来源）。

## 说明

- 需要 Windows 自带 .NET Framework 4.8
- 构建需要 .NET SDK 6.0 或更高版本
- 需要已安装 SolidWorks 2022
- 需要已安装 Bambu Studio
- 编译输出目录会包含 SolidWorks Interop DLL，exe 启动时需要它们在同一目录
- SolidWorks Interop 程序集统一放在仓库根 `lib\SolidWorks\`，更换 SolidWorks 版本时
  替换该目录内容即可，无需修改工程文件
- 配置统一保存在 `%APPDATA%\ModelExplorer\config.json`，主程序 / CLI / 插件共用
- 测试：`powershell -ExecutionPolicy Bypass -File .\build.ps1`，或直接运行
  `ModelExplorer.Tests\bin\Release\ModelExplorer.Tests.exe`
