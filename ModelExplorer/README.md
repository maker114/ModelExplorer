# Model Explorer

WPF 版 SolidWorks STL / Bambu Studio 3MF 工作台。

## 更新报告

### V3.1.3

#### 主界面

- 左侧「文件整理」改名为 **「STL/3MF文件整理」**，与旁边的「工程名整理」并列时表意更明确。
- 该框内的按钮文本现在跟随设置里的**按文件夹整理**开关，回显当前模式：
  - 开关打开 → 「**按文件夹整理文件**」

- 主程序 / Core / CLI / 测试更新至 3.1.3；SolidWorks 插件本次无改动。

### V3.1.2

#### 修复

- **单文件夹工程也能打开详细统计**：此前要求“零件/装配体来自多个文件夹”才允许打开，
  只有一个文件夹时会提示「当前只有单个文件夹，无需查看详细统计」并拒绝打开。由于侧栏
  统计已不再显示 STL / 3MF 数量，详细窗口是查看这些数量的唯一入口，该限制会让
  单文件夹工程完全看不到它们。现在只要扫描到文件就能打开。
- **详细统计不再丢掉分类文件夹里的文件**：汇总时原先会把位于 `STL文件夹` / `3MF文件夹`
  中的文件**整条跳过**，导致整理过的工程里 STL / 3MF 数量恒为 0。现在这些文件归入其
  所属的上级文件夹（`工程\子工程\STL文件夹` → `工程\子工程`），分类文件夹仍然不会
  单独成行，但各类数量都能统计到。
- 汇总逻辑从主窗口下沉到 Core 的 `FolderStatistics`，可被测试覆盖；
  新增 20 项测试，测试总数 78 → 98。

### V3.0.4

修复「整理」在已经整理好的工程上毫无反馈、并可能因目录不可写而整体失败的问题。

#### 修复

- **整理在工程已整理时不再“点了没反应”**：整理会跳过分类文件夹，所以当 STL / 3MF
  已经位于 `STL文件夹` / `3MF文件夹` 中时，结果必然是「移动 0 个」。此前界面上不弹
  任何窗口，日志只写「整理完成：STL 0 个，3MF 0 个」，很容易被误读成
  “扫描不到 STL / 3MF 文件”。现在会明确提示，例如：
  「本次没有需要移动的文件。已扫描到 STL 46 个、3MF 28 个，均已位于「STL文件夹」
  或「3MF文件夹」中。」日志也改为「整理完成：移动 STL 0 个、3MF 0 个；已有 STL 46 个、
  3MF 28 个位于分类文件夹中」。
- **整理不再预先创建根目录的分类文件夹**：原实现一进入整理就无条件创建工程根目录下的
  `STL文件夹` / `3MF文件夹`，若该处不可写（只读目录、权限不足、网络盘等）就会直接抛出
  「对路径…的访问被拒绝」并让整个整理失败。现在目标目录只在真正需要移动文件时才创建，
  **没有文件可整理时本功能完全不写盘**。
- **工程名检查在无需修改时也给出回执**：此前只写一行日志、不弹窗，界面看起来
  “点了没反应”。现在会弹出「工程名检查完成，没有需要修改的文件」，并列出本次扫描到的
  文件构成（零件 / 装配体 / STL / 3MF 各多少个），便于确认确实扫描过了。
- 「整理完成」这类纯告知弹窗只保留一个「知道了」按钮，不再出现容易误解的「取消」。
- 新增 6 项测试覆盖“已整理工程”的计数与“散落文件 + 已归类文件混合”场景，
  测试总数 70 → 76。

#### 版本

- 主程序 / Core / CLI / 测试更新至 3.0.4；SolidWorks 插件本次无改动。

### V3.0.0

本次为结构重构版本。界面、按钮、命名规则与整理行为与 V2.4.1 保持一致，
改动集中在工程结构、共享逻辑与工程化，并首次引入自动化测试。

#### 新增结构

- 新增 `ModelExplorer.Core` 共享库，承载扫描、工程名规则、整理、配置、STL 导出与
  Bambu Studio 启动；主程序、命令行工具、SolidWorks 插件全部改为引用它。
- 新增 `ModelExplorer.Tests` 测试工程，覆盖命名规则、扫描标记、归类整理与撤销，共 62 项断言；
  `build.ps1` / `publish.ps1` 会在构建后自动运行。
- 新增仓库级 `Directory.Build.props`（统一 net48 / x64 / LangVersion 等）与
  `.gitattributes`（统一换行符策略），以及根目录 `build.ps1`、`publish.ps1`。

#### 修复的结构缺陷

- **统一分类文件夹命名**：命令行工具原先写入 `STL文件`，而主程序使用 `STL文件夹`，
  导致 CLI 导出的 STL 在主程序中被误判为 `[未整理]` 并被重复搬移。
  现在该名称只有 `WorkspaceNames` 一处定义。
- **补齐缺失依赖**：插件所需的 `SolidWorks.Interop.swpublished.dll` 此前从未进入版本控制，
  只在编译输出目录里存在，克隆后插件无法编译；现已纳入 `lib\SolidWorks\`。
- **消除硬编码路径**：`D:\SW2022\SOLIDWORKS\` 原先出现在插件 csproj 与三个构建脚本中；
  现由 `Directory.Build.props` 的 `SolidWorksLibDir` 单点提供，任意机器均可离线构建。
- **统一配置**：主程序使用 `config.json`，而插件与 CLI 使用 `ModelExplorerAddin.config`，
  同一个“保留历史版本”开关在两侧互不生效；现已统一为 `%APPDATA%\ModelExplorer\config.json`，
  旧配置会一次性自动迁移（原文件改名为 `.migrated` 保留）。
- **解决方案不再残缺**：`.sln` 原先只挂载主程序，CLI 与插件连 IDE 都识别不到；
  现在 5 个工程全部纳入，且 CLI / 插件由 `csc.exe` 手工脚本改为标准 `dotnet build`。
- **删除重复实现**：STL 导出（偏好设置 + `SaveAs3` + 单位/质量映射 + 保留历史命名）此前在
  主程序、CLI、插件中各写一遍；Bambu 启动与 SendKeys 保存在主程序、CLI 中各写一遍。
  现已合并到 Core 的 `SolidWorksStlExporter` 与 `BambuStudioLauncher`。
- **收敛散落规则**：“装配体导出”判定原先在三个文件中各写一遍，现集中于 `AssemblyExportRule`；
  其中“扫描打标”与“重命名计划”是两套不同语义，刻意保留为两个具名谓词，
  以免重命名时剥掉已有的 `[装配体导出]` 标记。
- **消除领域层对 WPF 的依赖**：`ModelFile.TypeBrush` 使领域模型持有 WPF 画刷，
  扫描逻辑无法脱离界面框架测试；颜色改由界面层 `KindBrushConverter` 负责。
- **清理死代码**：删除 294 行完全无引用的 `FolderPickerWindow.cs`，以及无引用的
  `ModelFile.MatchText`。
- **主界面瘦身**：`MainWindow.xaml.cs` 由 1381 行降至 1126 行，内联的整理流程、
  两段近乎相同的撤销流程与四个私有辅助方法全部下沉到 Core 并可被测试。
- **发布目录名与版本一致**：新增 `publish.ps1`，目录名由程序集版本推导
  （此前 `dist\ModelExplorer-2.0.1-portable\` 中装的已是 2.4.1）。

#### 行为改进

- 设置窗口新增 STL 参数（二进制 STL、单位、质量），此前只能在 SolidWorks 插件里配置。
- 命令行工具现在会读取设置中的 `SLDWORKS.exe` 路径（此前只依赖 COM 注册）。
- 插件的设置保存不再覆盖主程序的设置（改为读取完整配置后只修改自己负责的字段）。
- CLI 的参数与退出码保持与 V2.4.1 一致（0 / 1 / 2 / 3 / 4），现有脚本可继续使用。

#### 升级注意

- 插件程序集版本变为 3.0.0.0，升级后需重新运行 `install.ps1` 才能被 SolidWorks 加载。
- 插件与 CLI 的旧配置文件会一次性迁移到 `%APPDATA%\ModelExplorer\config.json`。

## 功能规则说明

### 详细统计

- 点击左侧「统计」框（或其中的“点击查看详细统计…”）打开详细统计窗口，按**归属文件夹**
  列出零件、装配体、STL、3MF 的数量与总计。
- 工程只有一个文件夹时同样可以打开——详细窗口是查看 STL / 3MF 数量的入口
  （左侧统计框只显示零件、装配体与文件总数）。
- 位于 `STL文件夹` / `3MF文件夹` 中的文件**不会单独成行**，而是归入其所属的上级文件夹：
  例如 `工程\子工程\STL文件夹` 里的 STL 计入 `工程\子工程` 一行。这样分类文件夹不会
  产生额外行，同时各类文件的数量都能统计到。
- 尚未扫描到任何文件时点击会提示，不弹空窗口。

### 工程名整理 / 自动命名

- 当前“工程名”取当前选择工程目录的根文件夹名称。
- 根目录下的直接子文件夹会被识别为“子工程”，但 `STL文件夹` 和 `3MF文件夹` 不参与子工程识别。
- 子工程文件夹中的文件目标名使用 `工程名_子工程名_文件名`，例如根目录 `Model`、子目录 `Sub` 中的 `Part.sldprt` 会整理为 `Model_Sub_Part.sldprt`。
- 子工程文件夹内的文件若已带有工程名前缀但没有对应子工程前缀，会补齐为 `工程名_子工程名_文件名`。
- 普通零件 `.sldprt` 与 STL 文件名中，第一个 `_` 之前的部分视为旧工程名；没有 `_` 时视为没有工程名。
- 无工程名时生成“添加名称”：
  - `零件A.sldprt` → `工程名_零件A.sldprt`
  - `文件B.stl` → `工程名_文件B.stl`
- 已有工程名但前缀不等于当前工程根文件夹名时生成“修改”：
  - `旧工程_零件A.sldprt` → `工程名_零件A.sldprt`
  - 比较不区分大小写；前缀正确时不再改动。
- 装配体导出的 STL 使用另一条规则：
  - 只要文件名包含 ` - `，就按装配体导出 STL 处理。
  - 忽略 ` - ` 之前的内容，并取其后第一个 `_` 后面的部分作为主体。
  - 目标名保留当前工程名前缀，并在扩展名前追加 `[装配体导出]`。
  - 示例：`任意装配体名 - 任意旧工程_零件C.stl` → `当前工程名_零件C[装配体导出].stl`
  - 位于子工程文件夹时使用 `工程名_子工程名_主体[装配体导出].stl`。
- 工程名整理弹窗会显示“修改”和“添加名称”两类计划，并按文件类型分组：零件、装配体导出、STL。
- 弹窗顶部会醒目标出根工程名和本次涉及的所有子工程名，表格包含子工程列并优先按子工程名排序。
- 每个计划行默认勾选；上次执行时取消勾选的文件路径会保存，下一次仍默认不勾选。
- 只有勾选的项目会执行；执行时会跳过源文件已不存在或目标文件已存在的项目，不会覆盖同名文件。
- 已执行的工程名修改可通过“工程名整理”框中的“撤销工程名修改”反向恢复。
- 如果先执行工程名整理、再执行文件整理，两侧撤销记录会自动重定向，避免文件被移入分类文件夹后无法撤销工程名。

### 未整理 / 未对应标签

- `[未整理]` 只用于 STL 文件：
  - 文件不在当前工程根目录下的 `STL文件夹` 或 `3MF文件夹` 中时显示 `[未整理]`。
  - 已在分类文件夹中时不显示。
- `[未对应]` 用于 STL 文件：
  - 扫描时收集所有 `.sldprt` 与 `.sldasm` 的主文件名作为来源集合。
  - 如果 STL 主文件名在来源集合中不存在，则显示 `[未对应]`。
  - 比较时忽略 `[装配体导出]` 标记。
- 装配体导出 STL 豁免 `[未对应]` 检查：
  - 文件名包含 ` - `，或文件名带 `[装配体导出]`，统一视为装配体导出。
  - 这类文件不再显示 `[未对应]`，但仍会按目录位置判断是否显示 `[未整理]`。
- 右侧“选中模型”详情也遵循同一规则：装配体导出 STL 不显示“未对应/已对应工程文件”行。

### 自动整理 STL / 3MF

- 在左侧“文件整理”框中点击“整理 STL / 3MF 文件”执行。
- 程序递归扫描当前工程目录，但会跳过已有的 `STL文件夹` 与 `3MF文件夹`。
- 已经位于 `STL文件夹` / `3MF文件夹` 中的文件不会被再次移动：即使关闭“按文件夹整理”，
  它们也不会被重新汇总到工程根目录。若本次没有任何文件需要移动，程序会明确提示
  “没有需要移动的文件”并列出已归类数量，而不是毫无反应。
- `.stl` 文件移动到 `STL文件夹`，`.3mf` 文件移动到 `3MF文件夹`。
- 关闭“按文件夹整理”时：
  - 所有 STL 集中到工程根目录的 `STL文件夹`。
  - 所有 3MF 集中到工程根目录的 `3MF文件夹`。
- 开启“按文件夹整理”时：
  - 在每个文件所在目录下分别创建/使用 `STL文件夹` 或 `3MF文件夹`。
- 目标位置已有同名文件时会自动追加 `_2`、`_3` 等序号，不会覆盖已有文件。
- 整理完成后会删除空的分类文件夹，生成整理报告，并重新扫描刷新列表。
- “撤销整理”会按相反顺序把本次移动的文件移回原位置。

## 功能

- 选择 SolidWorks 工程目录，递归扫描 `.sldprt` 和 `.sldasm`
- 以深色卡片列表展示零件和装配体
- 点击模型后导出 STL 到 `模型目录\STL文件夹\`
- 自动打开 Bambu Studio 加载 STL
- 配置打印机/耗材后点击“保存 3MF”
- 保留历史版本、是否打开 Bambu、是否保存 3MF 可配置
- 设置页可配置 SolidWorks 路径，便于 API 调用
- 设置页可配置 Bambu Studio 路径
- 内置 6 套深色外观预设，支持字体大小调整
- 圆角无边框窗口、圆角按钮、拨钮开关、圆角滚动条
- 日志会显示 SolidWorks / Bambu Studio 启动阶段

## 构建

项目为 5 个工程的标准 solution：

| 工程 | 说明 |
| --- | --- |
| `ModelExplorer.Core` | 共享业务库：扫描、工程名规则、整理、配置、STL 导出、Bambu 启动 |
| `ModelExplorer` | WPF 主程序（界面与主题） |
| `ModelExplorerCli` | 命令行转换工具 |
| `ModelExplorerAddin` | SolidWorks 2022 插件 |
| `ModelExplorer.Tests` | 测试套件（命名规则、扫描、整理、撤销） |

一键构建并运行测试：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

发布便携版（目录名按程序集版本生成）：

```powershell
powershell -ExecutionPolicy Bypass -File .\publish.ps1
```

发布结束后会自动清理 `dist\` 中的旧版本：**默认只保留最新 3 个版本目录**
（当前版本 + 2 个历史版本），更旧的删除。也可以单独运行清理：

```powershell
powershell -ExecutionPolicy Bypass -File .\prune-dist.ps1
powershell -ExecutionPolicy Bypass -File .\prune-dist.ps1 -KeepVersions 2   # 只保留 2 个
```

`prune-dist.ps1` 依据目录名里的**版本号**排序（而不是修改时间），因此手工重排过目录
也不会误删较新的版本。若某个旧版本的程序正在运行、目录被占用，脚本只提示、不删除，
关闭该程序后重跑即可。

> 发布前请先关闭正在运行的 ModelExplorer：`publish.ps1` 需要覆盖同名版本目录，
> 程序在运行时目录内的 exe / dll 被占用，脚本会明确提示这一点而不是抛出原始错误。

单独构建主程序仍可双击 `ModelExplorer\build.bat`。也可用 Visual Studio / VS Code
打开 `ModelExplorer.sln`，5 个工程全部已纳入。

输出到 `bin\Release\`，运行其中的 `ModelExplorer.exe` 即可。

所有工程共享仓库根目录的构建配置：`Directory.Build.props`（目标框架、平台、
Interop 路径）与 `lib\SolidWorks\`（SolidWorks Interop 程序集的唯一来源）。

### Visual Studio 2022 XAML 实时预览

- 打开 `ModelExplorer.sln`，右键 `ModelExplorer` 设为启动项目，按 `F5` 调试运行。
- 主界面已迁移到 `MainWindow.xaml`，修改 XAML 后使用 `Alt+F10` 或工具栏的 `XAML Hot Reload` 实时应用。
- 调试时可打开 `调试 > 窗口 > Live Visual Tree` 查看和检查控件层级。

## 说明

- 需要 Windows 自带 .NET Framework 4.8
- 构建需要 .NET SDK 6.0 或更高版本
- 需要已安装 SolidWorks 2022
- 需要已安装 Bambu Studio
- 编译输出目录会包含 SolidWorks Interop DLL，exe 启动时需要它们在同一目录
- SolidWorks Interop 程序集统一放在仓库根 `lib\SolidWorks\`，更换 SolidWorks 版本时
  替换该目录内容即可，无需修改工程文件
- 配置统一保存在 `%APPDATA%\ModelExplorer\config.json`，主程序 / CLI / 插件共用
- 测试：`powershell -ExecutionPolicy Bypass -File .\build.ps1`，或直接运行
  `ModelExplorer.Tests\bin\Release\ModelExplorer.Tests.exe`
